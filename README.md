# Personal Blog

Простий персональний блог: React 19 + TypeScript + React Router + Tailwind CSS 4, зібраний за допомогою Vite.

Зміст сторінок (`src/pages`, `src/data/posts.ts`) не змінювався — лише прибрано залежність від Figma Make,
щоб проєкт можна було редагувати й деплоїти як звичайний Vite/React-проєкт.

## Технології
- **React 19** + **React Router 8** — SPA з клієнтським роутингом (`/`, `/archive`, `/post/:slug`, `/about`, `/contact`)
- **Tailwind CSS 4** (плагін `@tailwindcss/vite`, без окремого `tailwind.config.js`)
- **TypeScript**
- **Vite 8** — dev-сервер і збірка

## Локальна розробка

```bash
npm install
npm run dev
```

Продакшн-збірка:

```bash
npm run build
```

Результат з'явиться у папці `dist/` — це статичні файли (HTML/CSS/JS), готові до заливання на будь-який хостинг.

Перевірити збірку локально:

```bash
npm run preview
```

## Деплой на Hostinger

Проєкт — це **статичний SPA (Single Page Application)**. Node.js на самому сервері не потрібен:
збірка (`npm run build`) виконується один раз (локально або на будь-якому CI), а на Hostinger
заливаються вже готові статичні файли з `dist/`.

### Варіант A — Звичайний Web Hosting Hostinger (найпростіший, рекомендовано)

1. **Зібрати проєкт локально**
   ```bash
   npm install
   npm run build
   ```
   Після цього з'явиться папка `dist/`.

2. **Додати файл маршрутизації**
   Скопіюйте файл `.htaccess` (він у корені цього проєкту) у папку `dist/`, поруч із `index.html`.
   Він потрібен тому, що React Router обробляє маршрути (`/about`, `/post/...`) на стороні браузера,
   а Apache на Hostinger за замовчуванням не знає про ці "сторінки" і видасть 404 при прямому переході
   чи оновленні сторінки. `.htaccess` перенаправляє всі запити на `index.html`, і React Router вже сам
   показує потрібну сторінку.

3. **Залити файли на хостинг**
   - Увійдіть у **hPanel** → **Файли** → **Файловий менеджер** (або підключіться по FTP/SFTP,
     дані для підключення — у hPanel → "Хостинг" → "Деталі облікового запису FTP").
   - Перейдіть у папку `public_html` (це коренева папка вашого домену). Якщо там є стандартні
     `index.html` чи інші файли — видаліть їх.
   - Завантажте **весь вміст** папки `dist/` (а не саму папку `dist`) прямо у `public_html`,
     разом із файлом `.htaccess`.
   - Структура на сервері має виглядати так:
     ```
     public_html/
       index.html
       .htaccess
       assets/
         ...js, ...css файли
     ```

4. **Перевірити**
   Відкрийте свій домен у браузері. Перевірте не лише головну сторінку, а й перехід на
   `/about`, `/archive`, `/post/якийсь-slug` — і оновіть сторінку (F5) на кожній із них,
   щоб переконатись, що `.htaccess` працює і 404 не виникає.

5. **HTTPS**
   У hPanel увімкніть безкоштовний SSL (Let's Encrypt) у розділі **SSL** — Hostinger зазвичай
   робить це автоматично для нових доменів.

### Варіант B — Через Git (якщо є доступ до Git Deploy в hPanel)

Якщо ваш план Hostinger підтримує **Git-деплой** (hPanel → Хостинг → Git):

1. Запуште цей проєкт (без папки `dist`, вона в `.gitignore`) у ваш репозиторій.
2. У hPanel вкажіть репозиторій і гілку.
3. Оскільки Hostinger Git-деплой лише копіює файли репозиторію (Node.js на shared-хостингу не запускає збірку),
   збірку `dist/` все одно потрібно зробити локально і закомітити її окремо, або деплоїти саме зібрані файли
   у окрему гілку/репозиторій, яку і вкаже Git Deploy. Простіше й надійніше — Варіант A.

### Якщо у вас VPS Hostinger (не Shared Hosting)

На VPS можна або так само віддавати статичні файли через Nginx/Apache (аналогічно Варіанту A,
без потреби у `.htaccess` — правило переписування задається в конфігу Nginx/Apache), або запустити
`npm run build && npm run preview`/serve через Node.js процес-менеджер (наприклад, `pm2` + `vite preview`
чи простий `serve -s dist`), і виставити його за Nginx-проксі. Для звичайного персонального блогу
Варіант A (статичні файли) простіший і не потребує підтримки Node.js процесу.

## Структура проєкту

```
src/
  App.tsx              # кореневий компонент, підключає роутер
  routes.ts             # маршрути React Router
  main.tsx              # точка входу
  index.css             # глобальні стилі, теми (світла/темна), Tailwind
  data/posts.ts          # вміст постів блогу
  hooks/useTheme.ts       # перемикання теми
  layouts/Root.tsx        # спільний лейаут (шапка/футер)
  pages/                 # сторінки: Home, Archive, Post, About, Contact, NotFound
```
